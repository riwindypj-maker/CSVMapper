# Processing Core モジュール仕様

## この文書の責務

この文書は、CSV ストリーム処理、文字コード、書記素クラスタ、変換グラフ評価、プレビュー、出力を担当する共有 C++ Processing Core と React Native 境界の基本設計案を定義する。

## ステータス

macOS 先行で Processing Core の製品実装を許可する。順序 3 では C++ の `inspectInput`（ストリーム解析・入力項目生成・進捗/中止）と C++ テストまでを確定範囲とする。TurboModule、両 OS アダプター、Windows ホスト連携、ファイル置換 API は後続で確定する。

## この文書で扱う正本範囲

Processing Core の公開インターフェース、入出力、スレッド、中止、進捗、エラー、副作用、OS アダプター境界。

## 対象モジュール

- `ProcessingCore`: OS 非依存の共有 C++ ライブラリ
- `NativeProcessing`: React Native から利用する Turbo Native Module 契約
- `FileSystemPort`: Processing Core が所有するファイル情報、置換、削除の抽象契約
- `WindowsFileSystemAdapter`、`MacOSFileSystemAdapter`: `FileSystemPort` の OS 別実装

## 対象範囲

CSV 読込、文字コード検証・変換、書記素境界、グラフコンパイル・評価、プレビュー、CSV 出力、進捗、中止、一時ファイル管理。

順序 3 の確定実装範囲は次に限定する。

- `ByteSource` によるバイト供給（テスト用 `MemoryByteSource` を含む）
- 1MiB チャンクのストリーム CSV 解析と文字コード変換
- 同期 API の `inspectInput`（ファイル概要、文字コード、ヘッダー、表示名、データ行数・項目数、先頭データ行サンプル、問題）
- 進捗コールバックと中止フラグ参照
- 上記を検証する C++ テスト

## 対象外

ファイル選択ダイアログ、画面状態、Undo・Redo、キャンバス描画、セッション永続化、異常終了後の一時ファイル回収。

順序 3 では次も対象外とする。

- Turbo Native Module と React Native / Application / UI
- Windows ホストと `WindowsFileSystemAdapter`
- `FileSystemPort` の置換・同一実体検出（順序 7 向け）
- `preview` / `exportCsv` / `commitExport` / `discardExport` の実装

## 公開インターフェース

TypeScript 側の契約名を次のとおりとする。具体的なコード生成構文は各ホストの React Native 版に合わせる。順序 3 では C++ 同期 API として `inspectInput` 相当のみを実装し、TurboModule イベント境界は後続とする。

| 操作              | 入力                                                              | 成功結果                                                     |
| ----------------- | ----------------------------------------------------------------- | ------------------------------------------------------------ |
| `inspectInput`    | `operationId`、`ByteSource`、文字コード指定または自動、進捗/中止  | ファイル概要、文字コード、ヘッダー、表示名、行・列数、サンプル、問題 |
| `preview`         | `operationId`、入力ファイル参照、処理スナップショット、件数       | 出力列、表示用行、列問題、確定スナップショット ID            |
| `inspectCellPath` | スナップショット ID、行番号、出力項目 ID                          | 元入力と経由ブロックごとの結果                               |
| `exportCsv`       | `operationId`、入力・一時出力参照、処理スナップショット、出力設定 | 件数、処理時間、警告件数、一時ファイル参照                   |
| `commitExport`    | `operationId`、一時ファイル参照、最終出力参照                     | 確定した出力先                                               |
| `discardExport`   | `operationId`、一時ファイル参照                                   | なし                                                         |
| `cancel`          | `operationId`                                                     | 受付結果                                                     |

進捗、完了、失敗、中止は `operationId` を必須とする。公開 DTO は CSV 値をエラーとログ用項目へ含めない。成功結果のサンプル値は結果 DTO に含め、ログへは渡さない。

### 順序 3 の `inspectInput`（C++）

- 入力: `operationId`、`ByteSource`、`TextEncoding`（`AutoDetect` 可）、進捗コールバック、中止フラグ参照
- 中止確認: 256 レコードまたは 50ms の早い方、およびチャンク境界
- 進捗: 100ms 以上 250ms 以下に間引き可能なフック
- 重複ヘッダーの表示名だけを `氏名［N列目］` 形式にし、元ヘッダー文字列は変更しない
- 解析エラーは論理レコード番号と取得可能な開始・終了物理行を返す
- ヘッダーのみは成功とし警告を付ける
- 中止時は部分結果を確定しない

## 入力

### 処理スナップショット

- `schemaVersion`
- 一意な `snapshotId`
- ノード、端子、接続、ブロック設定
- 出力項目 ID、名称、順序
- プレビュー件数または出力設定

スナップショットは変更不能とし、Processing Core で構造、参照 ID、循環、入力数、必須設定を再検証する。画面側の検証済み状態だけを信頼しない。

### ファイル参照

ファイル参照は正規化パスに加え、取得可能な OS ファイル識別子、サイズ、更新時刻を含む。入力処理の開始時に注入された `FileSystemPort` 実装が現在値と照合し、選択後に置き換えられた入力を検出する。

## 処理

### CSV と文字コード

- 入力は 1MiB を初期値とする固定サイズバッファで読み、CSV パーサー状態をチャンク間で保持する。
- UTF-8 は不正バイト列を置換せずエラーにする。
- Windows-31J は ICU の `windows-932` 変換表を使い、fallback と代替文字への置換を無効にする。
- 自動判定順は CSV 形式仕様に従い、判定と CSV 解析を分離する。
- 出力では論理値を CSV エスケープした後、選択した文字コードへストリーム変換する。
- 書記素クラスタは ICU BreakIterator の文字境界で数える。
- ICU の版と変換データを両 OS で同一に固定する。

### グラフ評価

- スナップショット受領時に DAG、入力数、出力到達性を検証し、トポロジカル順を 1 回だけ生成する。
- 出力へ到達しないノードはレコード評価対象から除外する。ただし問題判定には含める。
- 各レコードではコンパイル済み順序に従い、同じ入力と設定から同じ結果を生成する。
- 文字列結合の入力順は接続時刻ではなくスナップショットのプロパティ順を使う。
- 行ごとの中間値はその行の評価終了時に解放する。

### プレビュー

- 最大 1,000 行だけを返し、入力 CSV 全体を保持しない。
- 500 列×1,000 行の結果は固定サイズのページへ分けて JavaScript 側へ渡す。
- 全セルの変換経路は保持せず、選択セルについて `inspectCellPath` で再評価する。
- 新しいプレビューが成功するまで前回確定結果を変更しない。

### 出力

1. 注入された `FileSystemPort` 実装が入力と最終出力の同一実体を拒否する。
2. 最終出力と同じディレクトリへ、推測困難で衝突しない名前の一時ファイルを排他的に作る。
3. ヘッダーと全データを変換・書込し、Windows-31J 表現不能と数式候補を全件検証する。
4. flush と close が成功した場合だけ一時ファイル完成とする。
5. 数式候補があれば値を返さず件数だけを返し、`commitExport` まで最終出力を変更しない。
6. `commitExport` の直前に入力と出力の実体を再確認し、OS の置換 API で確定する。
7. 失敗、中止、取消では一時ファイルを削除する。

既存ファイルの属性と権限は引き継がない。異常終了後の残存一時ファイルは次回起動時に探索しない。

## スレッドと中止

- 長時間処理は専用バックグラウンドジョブ 1 件で実行する。
- `cancel` は lock-free または短時間の排他で中止フラグを設定し、呼出元を待たせない。
- Processing Core は 256 レコード処理後または 50ms 経過時の早い方で中止を確認する。
- ファイル読込、文字コード変換、書込の各チャンク境界でも中止を確認する。
- 中止確定後は新しい進捗を送らず、一時ファイルを削除して中止イベントを返す。
- 進捗は 100ms 以上 250ms 以下の間隔にまとめ、UI 更新頻度を行数に比例させない。

## 出力

- 読込概要、プレビュー、セル経路、出力結果
- 値を含まない問題とエラーコード
- 処理件数、総件数を取得できる場合の進捗率、経過時間
- 最終確定前の一時ファイル参照

## エラー

| 区分         | 例                                 | 返却内容                                 |
| ------------ | ---------------------------------- | ---------------------------------------- |
| `INPUT_*`    | 読込不能、入力変更、文字コード不正 | レコード・物理行、値を含まない概要       |
| `CSV_*`      | 未閉じ引用符、項目数不一致         | レコード・物理行、値を含まない概要       |
| `GRAPH_*`    | 循環、不正接続、設定不足           | ノードまたは接続 ID、概要                |
| `ENCODING_*` | Windows-31J 表現不能               | 件数、最初のレコード番号。文字は返さない |
| `OUTPUT_*`   | 同一実体、容量不足、置換失敗       | 処理段階、既存ファイル維持可否           |
| `CANCELLED`  | 利用者中止                         | `operationId`、削除結果                  |
| `INTERNAL`   | 想定外障害                         | 相関 ID、値を含まない概要                |

ネイティブ例外をそのまま JavaScript へ返さず、上記の安定したエラーコードへ変換する。

## 副作用

- 入力ファイルの読込
- 最終出力と同じディレクトリでのエクスポート用一時ファイル作成・削除
- 利用者が確定した出力ファイルの作成・置換
- 値を含まない進捗・結果・エラーイベントの通知

入力 CSV の変更、マッピングの保存、外部通信、データベース操作は行わない。

## メモリ制約

- 使用量は `O(最大論理レコード + プレビュー結果 + グラフ + 固定バッファ)` とする。
- CSV 全体、出力全体、100 万行分の中間値を保持しない。
- 読込と書込のバッファ数に上限を持たせ、生成側が消費側を無制限に先行しない。
- 性能試験では Processing Core だけでなくアプリケーション全体の常駐メモリ増加を測定する。
