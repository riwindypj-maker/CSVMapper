# UI共通デザイン仕様

## この文書の責務

この文書は、画面横断のレイアウト、状態表現、文言、アクセシビリティ、デザイン制約を定義する。

## この文書で扱う正本範囲

UIの配置原則、共通コンポーネント、状態ごとの見た目、アクセシビリティ制約。

## 参照する正本

- 画面の表示と操作: `docs/specs/screens/`
- 操作性要件: `docs/non-functional.md`

## 対象範囲

メイン画面、プロパティ領域、プレビュー、出力関連ダイアログ、問題一覧。

## 対象外

ブランドカラー、ロゴ、最終的なピクセル値、OS標準ダイアログ内部。

## レイアウト

- メイン画面は上部ツールバー、左側素材領域、中央キャンバス、右側出力・プロパティ領域、下部プレビューで構成する。
- キャンバスを主要作業領域として確保し、左右・下部領域は大量項目でもスクロール可能にする。
- OS の表示倍率を変更しても主要操作が画面外へ固定されない構成とする。
- ダイアログは操作目的、設定、問題、確定・取消の順で理解できる配置にする。

## コンポーネント

- 入力ノード、編集ブロック、出力ノードは種別を文字と形状で区別する。
- 端子は入出力方向と接続可否を識別できる表示にする。
- エラー、警告、正常、選択中、処理中、未更新を共通状態として扱う。
- 進捗は率を算出できる場合は進捗率、それ以外は処理件数を表示する。

## 表示状態

- エラーはアイコン、見出し、説明を伴い、警告と色以外でも区別する。
- 接続不可の端子は選択できない外観と操作状態にする。
- プレビュー後に編集が発生した場合は「未更新」であることを明示する。
- 選択要素とキーボードフォーカスをそれぞれ視認できる。
- 処理中は対象操作の二重実行を防ぐ。

## 文言

- 専門用語だけに依存せず、利用者が次の操作を判断できる表現にする。
- 確認ダイアログでは破棄・上書き・中止の対象と結果を明示する。
- エラーには原因と修正方法を記載し、CSV の実値は表示しない。ただしプレビュー画面内で利用者が明示的に確認する値は除く。

## アクセシビリティ

- 主要操作をキーボードで実行できる。
- フォーカス順は画面の読み順と作業順に一致させる。
- ボタン、入力、ノード、端子、状態表示にアクセシブル名称を付ける。
- 色だけで意味を伝えない。
- OS の表示倍率とキーボードフォーカス表示を尊重する。
- 具体的なショートカットは各画面の基本設計時に決定し、OS標準との衝突を避ける。

## 未決定事項

なし。具体的な色、余白、寸法、ショートカット割当は実装上のデザイン決定であり、この仕様の制約内で基本設計時に確定する。
