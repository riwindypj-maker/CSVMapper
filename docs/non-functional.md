# 非機能要件

## この文書の責務

この文書は、CSVMapper の対応環境、性能、操作性、信頼性、セキュリティ、保守性、ログ、運用を定義する。

## この文書で扱う正本範囲

性能、セキュリティ、信頼性、操作性、保守性、ログ、運用などの非機能要件。

## 参照する正本

- プロジェクト範囲: `docs/requirements.md`
- CSV出力: `docs/specs/features/csv-export.md`
- UI共通仕様: `docs/specs/design/ui-conventions.md`

## 対象範囲

初期リリースの対応環境、性能、操作性、信頼性、セキュリティ、可用性、監視、ログ、保守性、運用。

## 対象外

外部監視サービス、クラウド処理、異常終了後の一時ファイル回収、Intel 搭載 Mac、Linux、Web、スマートフォン。

## 対応環境

- `NFR-ENV-001`: Windows 11 の 64 ビット環境で動作する。
- `NFR-ENV-002`: macOS 13 以降の Apple Silicon 搭載 Mac で動作する。
- `NFR-ENV-003`: Intel 搭載 Mac は初期リリース対象外とする。
- `NFR-ENV-004`: React Native、React Native Windows、React Native macOS を利用する。
- `NFR-ENV-005`: 基本設計前にキャンバス、接続線、ズーム、複数選択、ファイル操作、大容量 CSV の技術検証を完了する。
- `NFR-ENV-006`: Windows 版と macOS 版で同一の変換ロジックを利用する。
- `NFR-ENV-007`: 関連ライブラリのバージョンを固定し、両 OS で再現可能なビルドを管理する。

## 性能

| ID | 要件 |
|---|---|
| NFR-PERF-001 | 最大 100MB の CSV を処理できる。 |
| NFR-PERF-002 | 最大 100 万データ行を処理できる。 |
| NFR-PERF-003 | 最大 500 入力項目を処理できる。 |
| NFR-PERF-004 | 最大 500 出力項目を定義できる。 |
| NFR-PERF-005 | 最大 1,000 編集ブロックを定義できる。 |
| NFR-PERF-006 | CSV 全体をメモリ展開せずストリーム処理する。 |
| NFR-PERF-007 | プレビュー対象データだけをメモリに保持する。 |
| NFR-PERF-008 | プレビューまたは出力中は進捗表示を1秒以内の間隔で更新し、中止操作の受付状態を100ms以内に画面へ反映する。 |
| NFR-PERF-009 | 長時間処理の進捗を表示する。 |
| NFR-PERF-010 | 入力・出力ノードと編集ブロックを合計最大 2,000 個配置できる。 |
| NFR-PERF-011 | 基準端末は 4 コア以上の CPU、16GB 以上のメモリ、SSD を備える端末とする。 |
| NFR-PERF-012 | 100MB または 100 万行のうち先に到達する CSV の先頭 100 件を、プレビューボタン押下後 5 秒以内に表示する。 |
| NFR-PERF-013 | 100MB、10 列、直接マッピングだけの CSV を 120 秒以内に出力する。 |
| NFR-PERF-014 | 基準端末で最大ノード構成を表示した状態のノード移動と接続を、操作開始から表示反映まで 100ms 以内で処理する。 |
| NFR-PERF-015 | 出力またはプレビューの中止操作後 3 秒以内に処理を停止する。 |
| NFR-PERF-016 | 最大 CSV の各シナリオと最大ノード構成で、処理中のピーク常駐メモリ増加量を処理開始前から 1GiB 以下とする。 |

CSV サイズ、データ行数、入力項目数は独立した上限とし、他の上限を超えない個別シナリオで確認する。ノード構成の上限は、500 入力項目のそれぞれを 2 個の編集ブロックを経由して 500 出力項目へ接続する 2,000 ノードの有向非巡回グラフを基準とし、15 種類の編集ブロックを含める。最大ノード構成でも変換結果を誤らず、クラッシュせず、プレビューまたは出力を中止できることを合格条件とする。

`NFR-PERF-014` は、基準端末で最大ノード構成を表示し、10 回のウォームアップ後にノード移動と接続をそれぞれ 100 回測定した 95 パーセンタイルで判定する。`NFR-PERF-016` の 1GiB は 1,073,741,824 バイトとし、入力 CSV 選択直前の常駐メモリを基準に、プレビューまたは出力が完了するまでの最大増加量で判定する。処理時間とピークメモリは測定結果へ記録する。編集ブロック数や文字列長が基準シナリオを超える場合も測定結果を記録する。

## セキュリティ

- `NFR-SEC-001`: CSV データを外部サーバーへ送信しない。
- `NFR-SEC-002`: CSV データをクラウドへ保存しない。
- `NFR-SEC-003`: マッピング設定を恒久保存しない。
- `NFR-SEC-004`: 処理完了、失敗、中止時に処理用一時ファイルを削除する。
- `NFR-SEC-005`: アプリケーションログに CSV の項目値を記録しない。
- `NFR-SEC-006`: CSV データは入力ファイル、出力先、OS の処理用一時領域以外へ保存しない。
- `NFR-SEC-007`: エラーログに CSV のサンプル値、固定値、変換後文字列、個人情報を記録しない。

## 信頼性

- `NFR-REL-001`: 入力 CSV を変更しない。
- `NFR-REL-002`: 出力完了前に既存ファイルを変更しない。
- `NFR-REL-003`: 失敗または中止時に不完全な出力ファイルを残さない。
- `NFR-REL-004`: 同一の入力値とフローから常に同一結果を生成する。
- `NFR-REL-005`: 両 OS で同一の変換結果を生成する。
- `NFR-REL-006`: 編集ブロックの実行順を接続関係から一意に決定する。
- `NFR-REL-007`: 既存ファイルへの上書きは一時ファイルへの正常出力完了後だけ行う。

異常終了後の一時ファイルを次回起動時に検出・削除する機能は対象外とする。

## 可用性

- 外部サービスに依存せず、ネットワークへ接続できない状態でも主要機能を利用できる。
- 長時間処理の失敗または中止後も、アプリケーションを再起動せず編集と再実行へ戻れる。

## 操作性

- `NFR-USE-001`: プログラミング知識なしで主要操作を完了できる。
- `NFR-USE-002`: 接続可能な端子を識別できる。
- `NFR-USE-003`: 接続不可能な端子を選択できない。
- `NFR-USE-004`: エラー、警告、正常状態を色だけでなくアイコンと文字でも表す。
- `NFR-USE-005`: 主要操作をキーボードで実行できる。
- `NFR-USE-006`: 検索と自動整列により大量のノードから目的のノードを探せる。
- `NFR-USE-007`: OS の表示倍率を変更しても主要操作を実行できる。
- `NFR-USE-008`: 破壊的操作の確定前に確認を表示する。

## 監視

外部監視サービスは使用しない。利用者が処理中の進捗と処理後の成否をアプリケーション内で確認できるようにする。

## ログ

ログには起動・終了日時、アプリケーションバージョン、OS、処理開始・終了日時、入力ファイルサイズ、入力・出力の行数と項目数、編集ブロック数、成否、エラーコード、値を含まないエラー概要を記録する。

ログは OS 標準のアプリケーション領域へ保存し、1 ファイル最大 10MB、最大 5 世代でローテーションする。アプリケーションからのログ削除機能は初期リリース対象外とする。

## 保守性

- `NFR-MNT-001`: CSV 解析と画面処理を分離する。
- `NFR-MNT-002`: フロー実行とフロー描画を分離する。
- `NFR-MNT-003`: 編集ブロックを共通インターフェースで実装する。
- `NFR-MNT-004`: 新しい編集ブロックを追加しやすい構造にする。
- `NFR-MNT-005`: OS 固有処理を共通処理から分離する。
- `NFR-MNT-006`: 主要な文字列変換を単体テスト可能にする。
- `NFR-MNT-007`: 接続ルールと画面表示ルールを分離する。

## 運用

- 処理結果から出力件数、出力先、処理時間を確認できる。
- 配布、署名、インストーラー方式は技術検証で決定する。
